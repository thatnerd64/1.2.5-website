Architecture Comparison: Ahead-of-Time (AOT) vs In-Browser JVM

Metric TeaVM (AOT JS) Bytecoder (AOT WasmGC) OpenJDK Zero in Wasm (Method 1)
Execution Model Ahead-of-Time to JS Ahead-of-Time to WasmGC Real JVM Interpreter in Wasm
Standard Classlib Custom org.teavm.classlib Incomplete (lacks String.split) 100% Full OpenJDK 21 Classlib
Dynamic Mod Loading Simulated via static tree Unsupported (closed-world) Native URLClassLoader Support
Reflection Support Requires compiler metadata Very limited Full JVM Reflection API
Graphics Pipeline Custom GL1.1 → WebGL shims Raw WebGL 1.0 API only JNI → Canvas / GL4ES → WebGL
Why this is key for Minecraft 1.2.5 + Forge: AOT compilers fail on Forge modpacks because Forge synthesizes classes and scans JARs dynamically using ModClassLoader. With an embedded OpenJDK Zero interpreter inside WebAssembly, Minecraft's unmodified bytecode and mods run directly inside the JVM heap.

Minecraft 1.2.5 Integration Roadmap

  1. JVM Core: javabox-direct.wasm (3.1 MB) + javabox-direct.data (72 MB JDK image).
  2. Filesystem: Emscripten virtual MEMFS / IDBFS mounting .minecraft and assets.pak to browser IndexedDB.
  3. LWJGL 2.9.3 Bridge: Map LWJGL 2.9.3 C native JNI functions (liblwjgl.so) to Emscripten's WebGL / GL4ES rendering layer.
  4. Audio Bridge: Connect Paulscode 3D sound system to browser Web Audio API via ring buffers.
